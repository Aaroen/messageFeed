# Agent Global Memory

## 偏好设置

* 语言：始终使用中文回复
* 除非用户要求否则严禁直接或者间接（git等方式）删除文件或导致文件消失

## 写作风格

* 所有表述均采用学术化语言，客观呈现数据和分析，避免使用夸张修饰词和表情符号

## 代码规范

* 非用户要求不要创建任何sh脚本或py测试文件，尽可能保持代码库干净整洁
* 短程验证冒烟等测试时使用正式文件并命令行指定临时参数
* 所有和路径相关的配置等文件均使用相对路径，注意严格核实相对路径的正确性

## 测试规范

* 在测试阶段（已经完成所有实现），非必要尽量不要单独创建测试和调试脚本和文件
* 如果必要则要先创建文件夹统一管理这些文件并且调试完成之后统一删除
* 在实现要求时可以使用模块化的思想创建多个抽象文件来进行

## 文档规范

* 默认情况下，不要创建任何新的说明文档或文档文件
* 不要自动生成 README.md、设计文档、使用说明、架构说明等冗余文档
* 只有在用户明确给出"编写文档 / 生成 README / 写说明文档"等指令时，才允许创建或修改文档
* 避免生成冗余繁杂文档

## CodeGraph

当任务涉及理解代码结构、定位符号、分析调用链、评估影响范围或梳理跨文件依赖时，应优先使用 CodeGraph，再考虑使用 `rg`、`find` 或逐文件读取。

如果仓库根目录尚不存在 `.codegraph/` 目录，应先在仓库根目录执行 `codegraph init` 建立索引；索引完成后，再使用 CodeGraph 进行结构化分析。仅当初始化失败、当前目录不是可初始化的代码仓库，或用户明确要求不建立索引时，才退回基于文件结构和文本检索的分析方式。

- **MCP 工具**（可用时）：`codegraph_explore` 可用于一次性获取相关符号源码、调用路径和依赖关系。查询中应包含具体文件、符号名或结构性问题；如果结果列出但延迟加载某个实体，应按名称继续加载。
- **Shell 命令**（始终可用）：`codegraph explore "<符号名或问题>"` 可输出同类结果。

在已初始化仓库中，应通过 `.codegraph/` 判断索引是否存在，并优先基于索引结果开展分析。
